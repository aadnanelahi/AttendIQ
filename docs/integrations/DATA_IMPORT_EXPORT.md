# Data Import and Export

## Purpose
Bulk import/export of master data and business data for onboarding, migration, and interoperability per PRODUCT_REQUIREMENTS.md §12 and FUNCTIONAL_REQUIREMENTS.md §Reporting.

## Import
- Supported entities: employees, departments, designations, locations, users/roles, devices, shifts/rosters, leave balances, opening balances, attendance corrections.
- Formats: CSV, XLSX, and JSON; schema documented per entity with an import template downloadable from the UI.
- Preflight/dry-run mode reports row-level errors before any write.
- Idempotent: re-running with the same file must not create duplicates; employee number is the natural key for employee imports.
- Validation: required fields, enum values, cross-entity references (manager, department, location), and tenant-scoped uniqueness.
- Asynchronous processing with per-job status, progress, and error export.
- Role-restricted: only tenant administrators with import permission; every import job and result is audited (docs/security/AUDIT_LOGGING.md).

## Export
- Reports and payroll outputs export to CSV, XLSX, PDF (docs/reports/REPORTING_ENGINE.md, docs/payroll/PAYROLL.md).
- Payroll batch files (e.g. WPS) generated by country modules (docs/payroll/PAYROLL_COUNTRY_MODULES.md).
- Export jobs are tenant-aware and role-restricted; data never exported across tenants.

## API and Webhooks
- Programmatic import/export via versioned REST APIs (docs/api/API_SPECIFICATION.md).
- Webhooks notify on job completion and export readiness (docs/integrations/INTEGRATION_ARCHITECTURE.md).

## Limits and Scalability
- Chunked processing and queue-based background execution for large files (docs/architecture/SCALABILITY.md).
- File size and row-count limits configurable per tenant; oversized jobs rejected with clear guidance.
- Immutable copies of imported files retained per retention policy.
